# Andres Arbelaez | Designer & Creative Technologist

Portfolio site styled as a **Windows XP–style desktop** (Bliss wallpaper, taskbar, draggable windows). A **RAG-powered “AiOL Instant Messenger”** answers recruiter-style questions from your resume and project content, with strict grounding rules in the API. Optional **Portfolio Presentation** windows load album-style content from JSON.

- **Local dev**: If `OPENAI_API_KEY` is unset, chat and query embedding use **Ollama** (see below).
- **Production (e.g. Vercel)**: Chat **requires** `OPENAI_API_KEY`. There is no Ollama on the server; without the key, `/api/chat` returns **503** in production.

## What’s implemented

| Piece | Role |
|--------|------|
| **`app/page.tsx`** | Loads visible projects and presentation albums; renders **`DesktopShell`**. |
| **`DesktopShell`** | Desktop icons: AIM, Resume (external PDF link), optional Portfolio presentation, one folder per project. Manages **AIM**, **Notepad**, and **Presentation** windows and taskbar. |
| **`app/api/chat/route.ts`** | Embeds the latest user message, retrieves chunks from **`data/embeddings.json`**, streams a reply via OpenAI or Ollama. Reads **`content/agent-system-prompt.md`**. |
| **`scripts/ingest.ts`** (`npm run ingest`) | Chunks `content/resume.md` + `content/projects.json`, embeds, writes **`data/embeddings.json`**. |
| **`lib/retrieve.ts`** | Cosine similarity search over committed embeddings; optional boost so AI-tagged projects appear for AI-related questions. |
| **`app/project/[slug]/page.tsx`** | Simple project detail page (link targets from desktop/chat). |

## Content schema

- **`content/projects.json`**: Top-level object with a **`projects`** array (not a bare array). Each item follows **`types/project.ts`** (`title`, `slug`, `url`, `skills`, `summary`, plus optional fields like `hidden`, `topics`, `evidence`, etc.).
- **`content/resume.md`**: Markdown; chunked and embedded with projects.
- **Embeddings file**: Chunks have `id`, `content`, `embedding`, `source` (`"resume"` \| `"project"`), optional `projectId`. See **`lib/vector-schema.ts`**.
- **Presentation**: **`lib/presentation.ts`** loads defined album IDs from **`content/presentation/*.json`**. If at least one valid album exists, the Portfolio desktop icon appears.

## Run locally

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

- **Chat + RAG without OpenAI**: Run **Ollama**, pull **`nomic-embed-text`** and a chat model (default **`llama3.2`** unless you set `OLLAMA_CHAT_MODEL`). Optional: `OLLAMA_URL` if not `http://localhost:11434`.
- **Chat + RAG with OpenAI locally**: Set `OPENAI_API_KEY` (e.g. in `.env.local`); the app uses OpenAI for embeddings and chat the same way as production.

## Ingest (refresh embeddings)

After changing resume or projects:

```bash
# With OpenAI (recommended before committing embeddings for Vercel):
export OPENAI_API_KEY="sk-..."   # or use .env.local
npm run ingest
git add data/embeddings.json
git commit -m "Refresh embeddings"
```

Vercel does **not** run ingest; **`data/embeddings.json`** must be in the repo (or otherwise available at build/runtime) for retrieval to work on the live site.

## Deploy to Vercel

1. **Log in** (one-time): `npx vercel login`
2. **Deploy**: `npx vercel` or connect the Git repo in the [Vercel dashboard](https://vercel.com/dashboard) for automatic deploys.
3. **Production chat**: Add **`OPENAI_API_KEY`** under Project → **Settings** → **Environment Variables** for **Production** (and **Preview** if you want chat on preview URLs). Redeploy after saving.
4. **Optional**: `OPENAI_CHAT_MODEL` (default **`gpt-4o-mini`**).

### Custom domain

In Vercel → **Settings** → **Domains**, add your hostnames and point DNS (e.g. Namecheap) per Vercel’s instructions.

## Production AI checklist

1. [OpenAI API keys](https://platform.openai.com/api-keys): create a secret key (`sk-...`).
2. Vercel → your project → **Settings** → **Environment Variables** → **`OPENAI_API_KEY`** → Production (+ Preview if needed) → **Save** → **redeploy**.
3. Repo includes an up-to-date **`data/embeddings.json`** from `npm run ingest` with the same provider (OpenAI embeddings) you use in production, so query vectors match stored chunks.

If live chat returns a JSON error about the key not being configured, **`OPENAI_API_KEY` is missing or not applied to that deployment** (wrong environment, or redeploy needed after adding the variable).
